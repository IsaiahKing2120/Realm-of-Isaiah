01 / THE BUILD STORY

A problem worth working on.

01

Problem

A card shop needs an economy that feels alive. A card game needs rules that hold up when effects, combat, and turn order start interacting.

02

Build

The solution separates shop, economy, cards, rules, and persistence. That keeps the store simulation and card-game rules distinct while giving both room to expand.

03

Result

The project has separate card, rules, economy, shop, world, and persistence modules, a browser development client, and rule-focused test projects. The catalog and card renderer give the systems a visible surface while deeper interactions keep evolving.

DECISION 01

Give each system a clear responsibility.

Cards describe content. Rules resolve play. Shop and economy modules handle inventory, pricing, and purchasing. A visual redesign should not require rebuilding combat or pricing logic.

DECISION 02

Let formats reuse the same foundations.

EVERBOUND formats can share casting, turn flow, and combat while applying different deck rules. NULL//SHIFT has its own sector-control model instead of forcing a different game into the same rules.

DECISION 03

Make the interface a client of the rules.

The ASP.NET development client exposes a place to inspect cards and exercise the systems. The renderer keeps names, costs, and rules as live text separate from the illustrations.

04 / CURRENT STATE

Built so far. Building next.

In the development build

  • A data-driven EVERBOUND catalog and reusable card-rendering system.
  • Turn flow, stack/priority, combat, and format validation modules.
  • A local four-seat table, plus an EVERBOUND Standard CLI mode.
  • A separate NULL//SHIFT sector-control prototype and store-simulation modules.

The next iteration

  • Expand executable NULL//SHIFT effects beyond its current prototype actions.
  • Refine targeting, combat feedback, and interaction coverage.
  • Connect more formats to the shop loop; networked multiplayer remains future work.
PROTOTYPE SCOPE

The four-seat table is local play with NPCs, not four connected online players. NULL//SHIFT is experimental: some defined card types are not yet executable. The catalog screenshot shows the real UI with catalog data, not a running multiplayer match.

Details come from the playable-formats source archive, the curated catalog, and the development-client documentation. No online multiplayer or production-readiness claim is implied.
